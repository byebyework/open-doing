# UX 优化设计:注册资料、设置结构、提示 badge 化

日期:2026-11-06
状态:已与需求方确认的设计,经建造者检查修订,待写实现计划

## 背景与动机(Why)

项目已可用(本地 MySQL),需求方提出三类优化:

1. **注册资料**:现注册只有 用户名+密码;业务上需要昵称、性别、邮箱、电话等资料字段。
2. **设置语义混乱**:个人空间的"设置"是纯个人偏好,团队空间的"设置"实际是团队管理页——两处都叫"设置",语义混淆。个人设置应上移为系统级,团队设置应正名为团队管理。
3. **提示散落**:各页面的口径说明、筛选状态、信息块等以段落/灰字直接铺在页面上,噪音大;应收敛为可点击的 badge。全页面走查还发现若干问题(见走查清单)。

非项目:不改任务/看板/日历/分析的业务逻辑;不改权限模型;不做邮件/短信验证(邮箱电话仅存档展示);不改 frozen contracts(AppShell 的 props 形状、`(dashboard)/layout.tsx` 的 import 关系)。

## 已定决策

### 1. 注册与个人资料

**Schema**(`users` 加 4 列,Drizzle 迁移):

| 列 | 类型 | 约束 |
|---|---|---|
| `nickname` | varchar(50) | 可空;展示名允许重复,不加唯一约束 |
| `gender` | varchar(10),`'male' \| 'female' \| 'secret'` | 可空,NULL=未填写;**用 `identifierVarchar`(utf8mb4_bin)+ `$type`**,与 `status` 等枚举列同一模式(建造者定的实现口径) |
| `email` | varchar(255) | 可空,**全库唯一**;写入前 lowercase 归一化;索引用默认 collation(utf8mb4_0900_ai_ci,大小写+重音均不敏感)——这是有意选择,在 schema 头注释说明 |
| `phone` | varchar(20) | 可空,**全库唯一**;格式校验应用层做(宽松:数字/`+`/`-`,7-20 位) |

MySQL 唯一索引 NULL 互不相等:多人不填邮箱/电话不冲突,无需部分索引技巧。

**输入归一化**(注册与资料编辑同一套):trim 所有可选项;空串写 `null`(否则第二个空邮箱会撞唯一索引);email lowercase;phone 校验 7-20 位。

**注册表单**(`RegisterForm`):
- 必填:用户名、密码、确认密码(不变)。
- 选填:昵称(≤50 字符)、性别(三选单选)、邮箱(格式校验)、电话(格式校验)。性别控件用 vendored `radio-group`(若 vendored 集缺此原语则按 shadcn 规范补入并写头注释,不自造控件)。
- **唯一冲突错误映射(建造者发现的真问题)**:`isUniqueViolation` 只返回布尔,而 `registerUser` 把一切非 username 的 1062 当 UID 撞车重试 5 次——重复邮箱会误报为"UID 生成失败"。必须:从 MySQL 报错消息提取索引名(现有 `users_username_unique` 即此法),显式分派 `users_email_unique` / `users_phone_unique` → 字段级错误"该邮箱/手机号已被使用";**先判邮箱/电话再进 UID 重试循环**,`registerUser` 与 `updateProfileAction` 两处都要。

**显示名规则(核心,需求方已拍板)**:`displayName = user.nickname`(注册时**必有值**)。
- 注册时若未填昵称,**自动生成一次并写入 nickname**:格式 `user_<5位哈希后缀>`(如 `user_a3f9k`,种子取 uid)。语言无关,不存在跨语言一致性问题。
- 用户随时在 `/settings` 个人资料改昵称,全站生效(头像颜色按 uid 哈希,不随改名漂移)。
- 不落词表方案(晨风/Breeze 等),无 locale 参数、无 i18n 牵连。
- **头像颜色哈希改为按 uid**(现按用户名哈希,昵称一改颜色就变;日历已按 assigneeId 哈希,是现成先例)。
- **种子数据**:5 个 seed 用户 `nickname = username`,保留原型中的名字(林夏等)。
- **e2e**:`e2e/utils/flows.ts#registerUser` 填 nickname = username,现有名字断言保持有效。

**个人资料编辑**:个人设置页(新路由,见 §2)新增"个人资料"区:昵称、性别、邮箱、电话,校验同注册。`users/actions.ts` 加 `updateProfileAction`(每字段独立授权=本人,唯一冲突回字段)。

**对队友可见**:性别、邮箱、电话对队友展示——团队管理页成员表格加列;成员卡片/负责人信息处展示邮箱。

### 2. 设置结构调整

- **个人设置**:入口从个人空间导航**移除**,放入右上角头像用户菜单(与"退出登录"并列,加 ⚙ 图标);路由独立为 **`/settings`**,新页面放 **`app/(dashboard)/settings/page.tsx`**(必须在 `(dashboard)` 组内才能继承 AppShell 与 `requireUser()` 守卫;放组外则无壳无守卫)。页面内容 = 现有个人设置(密码/提醒/语言/项目排序)+ 新增"个人资料"区。
- **旧路由重定向**:`/space/personal/settings` → redirect `/settings`(避免 404)。
- **`lib/routes.ts` 加 `personalSettingsHref()`**。
- **团队管理**:团队空间导航"设置"→ 改名**"团队管理"**;路由保持 `/space/{teamSlug}/settings`(面包屑、通知 href、团队 e2e 不受牵连);页面标题/文案同步"团队设置"→"团队管理"(内容不动)。
- **导航实现(建造者纠正)**:导航项**不是**数据驱动——`SpaceNavData` 只携带团队列表/计数,条目是 `SpaceNavMenu.tsx` 里硬编码的五模块数组,个人/团队渲染同一份。需改为按空间区分:个人空间 4 项(无设置),团队空间 5 项(末项"团队管理");移动端抽屉共用该组件,一处改。更新模块导航的文档注释。
- i18n:zh/en 目录同步;`settingsTitle`/`teamSettingsTitle` 等文案键更新;新增 `personalSettingsTitle`。
- **e2e 受影响面(建造者清点)**:flow 09(点击侧边栏设置入口、断言 `/space/personal/settings`)、flow 11(抽屉第 5 项"设置")、flow 12(硬编码旧路由)、responsive.spec(标题"团队设置")——随实现更新。

### 3. 提示 badge 化 + 页面走查修复

**规则**:页面标题下的一句话简介**保留**;其余次级说明(统计口径、基准日期、辅助说明块、表单提示)**收敛为 ⓘ badge,点击弹 Popover 展示**(悬停 tooltip 不用——按需求方"点击可以查看")。新组件 `HintBadge`(vendored Popover + ⓘ 图标,token 变量着色),支持传入标题 + 条目列表或富文本。

**badge 的信息分层(建造者发现的关键约束)**:Radix Popover 内容是 portal + 点击前不渲染——若把"当前筛选: 全部项目 · 13 个未完成任务"这类**实时状态**整个塞进弹层,SSR 测试与 e2e 可见文本断言全挂,且用户失去一眼可见性。因此:
- **触发器上直接显示实时摘要**(计数/日期等短文案,随 RSC props 更新),弹层放完整解释;
- SSR 测试(KanbanStatStrip.test 等)与 e2e 断言改为断言触发器文本,或先点击展开再断言弹层内容。
- **需要行动/警示的内容不 badge 化**:`remindersDisabledAlert`、危险操作确认里的说明等保持直显。

**已知转换点清单**(走查实证,含页面):
- 看板(个人+团队):"口径:已完成按近 7 天…"、筛选状态行(触发器显实时摘要)、"基准日期"角标
- 仪表盘(个人+团队):底部 ℹ 信息块("列表只保留「今天该看的」…")
- 日历(个人+团队):"未指派 任务也会按截止日期出现在日历上"、"基准日期"
- 分析(个人+团队):图表角落"近 30 天 · 按日 · 共完成 4 项"类口径行
- 登录页:"v1 暂不支持找回密码"
- 注册页:UID 信息块
- 团队管理页:各分区 paragraph 说明(邀请成员/凭码加入/危险操作)
- 个人设置页:提醒/排序的说明块

**实现阶段必须调用 `ui-ux-pro-max` 与 `frontend-design` 技能**做 badge 视觉与页面细节设计(需求方指定);`docs/prototypes/` 仍冻结,新组件遵循现有 token。

## 验收标准

1. 新注册用户:选填资料不填 → 各处显示自动生成名;填了昵称 → 全覆盖;邮箱/电话唯一冲突 → **对应字段级**错误提示(不是 UID 失败)。
2. 老用户(无昵称)界面显示名 = 生成名,其余不变;在 `/settings` 补填后全站生效;头像颜色不随改名漂移。
3. 用户菜单含"个人设置"入口;`/settings` 独立路由可用;旧 `/space/personal/settings` 重定向;个人空间导航无"设置";团队空间导航为"团队管理"。
4. 各页次级提示以 ⓘ badge 呈现(触发器保留实时摘要),点击展开;一句话页头简介保留;警示类内容不隐藏;i18n zh/en 全量。
5. 走查清单 P1-P5 修复;迁移可重放(空库 migrate+seed);ARCHITECTURE.md 与 v1 设计文档同步;全部门禁绿(lint/test/typecheck/e2e,含更新后的 flows 09/11/12、responsive、KanbanStatStrip)。
